# Badges and titles (B1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Award the 15 B1 badges from recorded check-ins, hosting and group ownership. Show each new badge once, keep a profile shelf, and let a person show one earned badge as a title on rosters.

**Architecture:** Badges are derived on read by SQL functions in the `app` schema. Only "seen" markers and the chosen title are stored. Hono routes under `/api/me/*` call `api.*` RPCs with the verified actor. A browser-safe catalog in `@rallypoint/domain/badges` holds names, sentences and art, and React components draw Medallions as inline SVG.

**Tech Stack:** Supabase Postgres (plpgsql/sql functions, migrations), Hono + Zod, Next.js App Router (client components), node:test integration tests against the local stack.

**Spec:** `docs/superpowers/specs/2026-10-22-reclub-competitive-analysis-design.md` (sections "Badges and titles (D-16)" and "Design direction (D-15)").

## Global Constraints

- Badges never read payments, fees, waitlist position, no-shows or reliability; no ranking, streak loss, push or email.
- Derived, not stored: correcting or cancelling the evidence removes the badge and any title built on it.
- "Checked in" = seat 1 of a `confirmed` party is `checked_in` in a session whose state is not `cancelled`; count distinct sessions.
- People met = distinct other accounts whose seat 1 was checked in at a session where yours was; guests never count.
- Ran a session = actor recorded at least one `checked_in` row in `app.attendance_changes` for a non-cancelled session.
- Full House = a session you ran where confirmed seats ≥ `details.capacity`.
- Profile is visible only to its owner. A title appears only on rosters the viewer may already read.
- Copy follows D-13: no internal terms, each fact said once. Every status has an icon and words. Reduced motion disables the glow animation.
- No new dependency. Inline SVG only.

## Review Focus

1. A check-in corrected back to unrecorded after a badge was shown and chosen as a title: the badge and roster title disappear (Task 2 test `correction removes the badge and its title`).
2. An existing active player opens the app for the first time with several earned badges: one sheet, the newest badge, "+N more", and one dismissal marks all seen (Task 1 `newestUnseen` test; Task 2 `seen markers` test).
3. A forged request marks unearned or malformed ids seen, or sets a title the person hasn't earned: it's ignored or refused with 422 (Task 2 tests).
4. A session cancelled after check-ins stops counting (Task 2 test `cancelled sessions do not count`).
5. A no-show or a waitlisted person earns nothing (Task 2 test `no-shows and waiting earn nothing`).

**Interfaces (produces):**
- `type BadgeKey = "first-rally" | "regular" | "sessions-10" | "sessions-25" | "sessions-50" | "sessions-100" | "off-the-bench" | "plus-one" | "new-faces-10" | "new-faces-25" | "new-faces-50" | "host" | "hosted-10" | "full-house" | "founder"`
- `type BadgeFamily = "playing" | "people" | "hosting"`
- `type BadgeGlyph = "rally" | "regular" | "number" | "bench" | "plus" | "faces" | "host" | "full" | "founder"`
- `interface BadgeDefinition { key; name; family; perGroup: boolean; glyph; label?: string /* number text */; colors: [string, string]; darkGlyph: boolean; sentence: string /* uses {group} */ }`
- `const badgeCatalog: readonly BadgeDefinition[]` in spec order with the spec's names
- `parseBadgeId(id: string): { key: BadgeKey; groupId: string | null } | null`. A per-group key requires `:<lowercase uuid>`; others must have no suffix.
- `badgeDefinition(key: BadgeKey): BadgeDefinition`
- `interface EarnedBadge { id: string; key: BadgeKey; groupId: string | null; groupName: string | null; earnedAt: string; seen: boolean }`
- `interface BadgeProgress { key: BadgeKey; groupId: string | null; groupName: string | null; current: number; target: number }`
- `interface RosterTitle { key: BadgeKey; groupName: string | null }`
- `interface BadgesView { earned: EarnedBadge[]; progress: BadgeProgress[]; title: (RosterTitle & { id: string }) | null; stats: { played: number; hosted: number; groups: number } }`
- `titleLabel(t: RosterTitle): string` gives `"Regular · Sunday Dink"` or `"First Rally"`
- `earnedSentence(b: { key: BadgeKey; groupName: string | null }): string`
- `newestUnseen(earned: EarnedBadge[]): { badge: EarnedBadge; more: number } | null` uses the newest `earnedAt`, and ties go to catalog order
- `nextBadge(progress: BadgeProgress[]): BadgeProgress | null` picks the highest `current/target`, then the fewest remaining, then catalog order. Entries with `current <= 0` or `current >= target` are ignored.

### Task 2: Derived badges, seen markers, titles and routes

**Files:**
- Create: `supabase/migrations/20261022170000_badges.sql`, `apps/api/src/badges.ts`
- Modify: `apps/api/src/index.ts` (mount `badges`)
- Test: `tests/badges.test.mjs`

**Interfaces:**
- Consumes: badge id format from Task 1.
- Produces (SQL, all `security invoker set search_path=''`, executable only by `service_role`):
  - tables `app.badge_views(user_id, badge_id, seen_at)` PK `(user_id, badge_id)` and `app.user_titles(user_id PK, badge_id, updated_at)`. Both have RLS on and no browser grants. Index `app.attendance_changes(actor_id)`.
  - `app.earned_badges(p_user uuid) returns table(id text, badge text, group_id uuid, group_name text, earned_at timestamptz)`
  - `app.badge_progress(p_user uuid) returns table(badge text, group_id uuid, group_name text, current integer, target integer)` covers the next sessions milestone, `regular` per group below 5, the next new-faces milestone, and `hosted-10` once hosted ≥ 1
  - `app.visible_title(p_user uuid) returns jsonb` gives `{key, groupName}` only while the chosen badge is still earned
  - `api.read_my_badges(p_actor_id uuid) returns jsonb` in the `BadgesView` shape. `played` = checked-in sessions, `hosted` = sessions run, `groups` = groups with any role.
  - `api.mark_badges_seen(p_actor_id uuid, p_ids text[]) returns jsonb` records only currently earned ids and returns `read_my_badges`
  - `api.set_my_title(p_actor_id uuid, p_badge_id text) returns jsonb`. `null` clears; an unearned id raises `check_violation` with message `title_not_earned`.
  - `app.registration_view_before_split` is replaced with an identical body plus `'title', app.visible_title(p.user_id)` in both roster branches
- Produces (HTTP):
  - `GET /api/me/badges` → `BadgesView`
  - `POST /api/me/badges/seen` with `{ ids: string[] }` (1–50 ids, each passing `parseBadgeId`) → `BadgesView`; bad input → 422 `invalid_badges` "Choose badges to mark as seen."
  - `POST /api/me/title` with `{ badgeId: string | null }` → `BadgesView`; malformed → 422 `invalid_title` "Choose one of your badges."; unearned → 422 `title_not_earned` "You can show a badge once you've earned it."
  - Any other method on these paths → 405. No token → 401.

  - `a first check-in earns First Rally, unseen until marked seen`: join, co-host checks seat 1 → `earned` has `first-rally` with `seen:false`, `stats.played === 1`; POST seen → `seen:true`; `progress` contains `regular` 1/5 with the group name and `sessions-10` 1/10
  - `a guest check-in earns Plus One`: party of 2, check seat 2 only → `plus-one` earned, `first-rally` not earned
  - `people met counts other accounts, not guests`: two fresh players checked in at one session → each has new-faces progress `current === 1`
  - `running check-in earns Host and a full session earns Full House`: capacity-1 session, one player joins, co-host checks in → the co-host has `host` and `full-house`, `stats.hosted === 1`
  - `starting a group earns Founder for that group`: fresh user POSTs `/api/groups` → `founder:<groupId>` with that group name
  - `titles: only earned badges, null clears, and rosters show them`: a title of `host` from a player → 422 `title_not_earned`; `{badgeId:"nope"}` → 422 `invalid_title`; set `first-rally` → another confirmed player's roster view shows `title: {key:"first-rally", groupName:null}` for that person; `{badgeId:null}` → title null

  - `seen markers ignore badges not earned`: POST seen `["sessions-100"]` → 200 and `select count(*) from app.badge_views where user_id=…` is 0; 51 ids → 422
  - `no-shows and waiting earn nothing`: ended session, seat marked `no_show` → no badges; a waitlisted party → no badges
  - `cancelled sessions do not count`: after a check-in, `update app.sessions set state='cancelled'` via `sql()` → `first-rally` gone
