# Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let people edit their name and the activities they play, open anyone's profile from a roster name (signed in or not), and show one current name for each account everywhere in RallyPoint.

**Architecture:**
- A new `app.profiles` table holds one row per person: an opaque `profile_id`, a saved name override, the last-seen account name and activities. It's reached only through `api.*` functions.
- "One name everywhere" works at write time. Saving a profile copies the person's effective name into every stored name column keyed by their account id. So every existing read, email and history line shows it with no change to those reads.
- Rosters gain a `profileId` per entry, so names can link to `/people/{profileId}`, a public view-only page.

**Tech Stack:** Next.js 16 App Router (`apps/web`), Hono + Zod (`apps/api`), Supabase Postgres plpgsql, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-24-profile-editing-design.md`

## Global Constraints

- **Name:** trimmed, 1–80 characters counted as Unicode code points (`[...s].length` in JS, `char_length` in SQL). An empty or blank saved name means "no override".
- **Effective name** = saved name, else account name (Google `full_name`, else the email before "@", else `"Participant"`).
- **Activities:**
  - At most 10 in total, at most 3 custom (not in `presetActivities`), custom names 1–40 characters.
  - Unique, ignoring case and outer spaces.
  - Each has `level` set to one of `"beginner" | "intermediate" | "advanced"` or to `null`.
  - The labels are "Beginner", "Intermediate" and "Advanced", and the line reads "Plays: Pickleball (Intermediate), Badminton".
- **Public profile fields only:** `profileId`, `name`, `title`, `badges`, `stats`, `activities`. Never email, user id, dues, payments, no-shows, groups, group names or sessions. Badges and title are shown without group names.
- **Profile URLs** use `profile_id`, a random uuid that is never the account id. An unknown id gets a 404 and "Profile not found".
- **Shared Auth metadata is never written.**
- **The person always comes from the verified session.** `POST /api/me/profile` replaces the whole profile. Unknown fields get a 400 `invalid_input`. The last save wins.
- **Copy:**
  - Edit screen title "Edit profile".
  - Note "Anyone with your profile link can see this."
  - Email line "Signed in as {email}".
  - Discard prompt "Discard your changes?"
  - Level hint "Your own rating."
  - Public page level marker "self-rated".
- D-13 plain words. Accessibility: labels, focus, 44px targets, `aria-expanded`/`aria-invalid` where relevant.
- Synthetic data only. The dev server is at `http://127.0.0.1:3101`. Never reset the shared local DB. Stop the server before `pnpm check`.

## Review Focus

1. **Emoji and accented names at the 80-character limit.** These must count the same in JS and SQL: 80 code points pass, 81 fail. Tests in Tasks 1 and 2.
2. **A roster person with no profile row** (from before the backfill, or never seen since) shows their name unlinked and never errors. Test in Task 3.
3. **Clearing a saved name** puts the account name back on old records too. Test in Task 3.
4. **A public profile must never leak group names** through badges or the title. Test in Task 2.
5. **A blank or spaces-only name** saves as "no override". It must not be rejected and must not be stored as spaces. Tests in Tasks 1 and 2.

### Task 2: Store, edit and publish profiles

**Files:**
- Create: `supabase/migrations/20261024090000_profiles.sql`
- Create: `apps/api/src/profiles.ts` (routes; mounted the way `badges.ts` is mounted from `apps/api/src/index.ts`)
- Modify: `apps/api/src/identity.ts` (add `actorName`)
- Modify: `apps/api/src/index.ts` (`/me`)
- Test: `tests/profiles.test.mjs`

**Interfaces:**
- Consumes: `normalizeProfile`, `ProfileInput`, `MyProfile` and `PublicProfile` (Task 1).
- Produces:
  - **Table** `app.profiles(user_id uuid primary key references auth.users on delete cascade, profile_id uuid not null unique default gen_random_uuid(), display_name text check (display_name is null or char_length(display_name) between 1 and 80), account_name text not null check (char_length(account_name) between 1 and 80), activities jsonb not null default '[]' check (jsonb_typeof(activities)='array'), updated_at timestamptz not null default now())`.
    - RLS on.
    - No browser grants.
    - Backfill one row for every user id found in `app.parties` or `app.group_roles`. Use `account_name` = the latest `parties.primary_name` for that user, else their email before "@", else `"Participant"`.
  - **`api.ensure_my_profile(p_actor_id uuid, p_account_name text) returns jsonb`**:
    - Inserts the row if it's missing, otherwise refreshes `account_name` when it changed.
    - Returns `{ profileId, name }`, where `name` = `coalesce(display_name, account_name)`.
  - **`api.read_my_profile(p_actor_id uuid, p_account_name text) returns jsonb`**: returns a `MyProfile`. It ensures the row first.
  - **`api.save_my_profile(p_actor_id uuid, p_account_name text, p_name text, p_activities jsonb) returns jsonb`**:
    - Takes a per-actor advisory lock.
    - Re-validates in SQL: length, counts, levels and duplicates, raising `check_violation` with message `invalid_profile`.
    - Upserts, then calls `app.propagate_name(p_actor_id)` (Task 3 fills its body; this task creates it as a no-op).
    - Returns `read_my_profile`.
  - **`api.read_profile(p_profile_id uuid) returns jsonb`**:
    - Returns a `PublicProfile`, or raises `no_data_found` with message `profile_not_found`.
    - Badges come from `app.earned_badges(user)` mapped to `{ key, earnedAt }`, and the title from `app.user_titles` mapped to `{ key }`. Neither includes a group name.
    - Stats use the same three counts as `api.read_my_badges`.
  - **API helper** `actorName(c, fallback: string): Promise<{ name: string; profileId: string }>` in `identity.ts`. It calls `ensure_my_profile` with `displayName(c.var.user, fallback)` as the account name.
  - **Routes:**
    - `GET /api/me/profile` returns `{ profile: MyProfile }` (requireUser).
    - `POST /api/me/profile` with body `{ name: string, activities: ProfileActivity[] }`. Zod `.strict()` is followed by `normalizeProfile`. Errors return a 400 `invalid_input` with `{ errors: ProfileError[] }`. It returns `{ profile: MyProfile }`.
    - `GET /api/people/:profileId{uuid}` returns `{ profile: PublicProfile }`. It needs no auth, and an unknown id gets a 404 `not_found` with "Profile not found".
    - `GET /api/me` adds `profileId`, and `displayName` = the effective name.

## Recovery

- The profile migrations add `app.profiles` and its functions. The name propagation (run on every save, and once for every profile by the profile-fixes migration) overwrites the stored name copies on parties and on six history tables (fee changes, attendance changes, split-claim changes, split runs, session cancellations and payment instructions). Actor ids and timestamps are not changed.
- Before migrating a non-local database, take a backup (D-08).
- Rolling back means reverting the application code and keeping the schema: the new table and functions are unused by older code, so nothing needs dropping.
- Earlier name copies can only be recovered from that backup.
