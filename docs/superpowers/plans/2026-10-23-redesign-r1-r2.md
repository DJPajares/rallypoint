# Quiet redesign R1 + R2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship pesos with a sensible default currency, the first shared quiet UI parts, and the organizer's game-day view of a session (one-tap check-in, a person sheet, stats and filters).

**Architecture:** Add PHP to the domain currency map and the three database checks. One migration recreates `app.save_session_before_cancellation` from the live definition with only the currency list changed. Game-day numbers and filters are pure functions in `@rallypoint/domain/game-day`. The screen reuses the existing attendance, fee and split controls inside a person sheet and adds one quick check button per party. No API or permission changes for R2.

**Tech Stack:** Supabase Postgres migration, TypeScript domain package, Next.js client components, `@rallypoint/ui`, node:test.

**Spec:** `docs/superpowers/specs/2026-10-23-quiet-redesign-design.md` (sections 1, "Shared building blocks", "Fixes along the way"); D-13, D-15, D-17.

## Global Constraints

- Keep every URL, consent text, recovery flow (**Check result** and **Retry same request**), queue, fee, payment and attendance rule, and authorization exactly as they are.
- Use tokens only (`tests/design-tokens.test.mjs`). No new dependencies. Targets are at least 44px, status is never shown by color alone, and reduced motion is respected.
- Never show or ask for the time zone (D-13). Currency defaults from the device; the organizer can still change it.
- PHP has 2 decimal places. A `fee_obligations` or `split_runs` row is never rewritten.

## Review Focus

1. **An interrupted quick check-in:** the row keeps the existing recovery block and never shows "here" until the server confirms it (Task 4 browser check).
2. **A two-seat party** where only the guest has arrived: the row says who is missing, and the quick button acts on the primary seat only (Task 3 `partyStanding` test).
3. **A withdrawn party that still owes a late-cancellation fee:** it stays visible under "To pay" (Task 3 `filterParties` test).
4. **A PHP amount with three decimals** is rejected by both the domain and the database (Task 1 tests).
5. **Cancelled sessions** keep the plain "Registration records" roster, with no check buttons (Task 4 browser check).

### Task 3: Game-day rules

**Files:** Create `packages/domain/src/game-day.ts` (export `./game-day`); test `tests/game-day-domain.test.mjs`.

**Interfaces (produces):** `type Roster = RegistrationView["roster"]`.
- `gameDaySummary(roster): { here: number; expected: number; toPay: number; waiting: number }`.
  - `here` = checked-in seats of confirmed parties.
  - `expected` = seats of confirmed parties.
  - `toPay` = parties of any state whose fee is `due`, not marked paid, and above zero.
  - `waiting` = waitlisted parties.
- `partyStanding(p): { seatsHere: number; seats: number; missing: string[] }`. `missing` lists the names of confirmed seats not checked in, using the guest name or "Guest".
- `paymentWords(p, money: (currency, minor) => string): string`: "Paid", "₱400 to pay", "Waived", "Share pending", or "" when there's no fee.
- `type GameDayFilter = "everyone" | "not_here" | "to_pay"`.
- `filterParties(roster, filter): { confirmed: Roster; waiting: Roster; left: Roster }`.
  - *everyone*: all confirmed; waiting in queue order; left = withdrawn or removed parties that still have a fee record.
  - *not_here*: confirmed parties missing any seat; nothing else.
  - *to_pay*: every party with an unpaid due fee, grouped the same way.

- [ ] Write failing tests:
  - `summary counts here, expected, to pay and waiting`
  - `a guest-only arrival lists the primary as missing`
  - `to pay keeps a withdrawn party that still owes`
  - `not here hides waiting and left parties`
  - `payment words`
- [ ] Run them (FAIL), implement, run them (PASS), then `pnpm --filter @rallypoint/domain typecheck`.
- [ ] Commit: `Add game-day counts and filters`.
